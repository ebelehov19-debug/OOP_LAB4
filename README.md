# Лабораторная работа 4 — вариант 12, «Банк»

Структура:

- `include/` — заголовки `Bank_Optional`, `Deposit`, `Credit`, `Card`, `BankCollection`.
- `src/` — реализации классов.
- `tests/` — тесты Google Test.

Ставки задаются долями: `0.1` означает 10%. Для аннуитетного кредита
месячная ставка равна `rate / 12`. При нулевой ставке годовой платёж равен
`sum / years`.

## Сборка и тесты

Требуются CMake 3.20+, компилятор C++20 и Ninja для приведённых команд.
Google Test берётся из установленного пакета или скачивается при первой
конфигурации через FetchContent.

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

## Коллекция

`BankCollection` хранит указатели на `Bank_Optional` в собственном динамическом
массиве. Вместимость увеличивается вдвое при заполнении. Успешный `add()`
передаёт владение объектом коллекции; при исключении объект остаётся у вызывающего.
Нельзя передавать указатель на локальный объект или объект другого владельца.
`nullptr` и повторное добавление того же указателя отклоняются.

`remove(index)` удаляет продукт и сдвигает оставшиеся элементы. Деструктор
удаляет все продукты через виртуальный деструктор базового класса и освобождает
массив. Копирование создаёт независимые объекты через `clone()`; при ошибке
копирования временные объекты освобождаются, а цель присваивания сохраняется.
Перемещение передаёт владение массивом, оставляя исходную коллекцию пустой
и пригодной для повторного использования.

Обход выполняется по индексам от `0` до `size() - 1` через `at()`.
Перегрузка `at()` для константной коллекции возвращает константную ссылку.
Некорректный индекс вызывает `std::out_of_range`.
`totalMetric()` суммирует метрики, для пустой коллекции возвращает `0`.

Индивидуальное задание варианта 12 реализовано в `sortByMetric()`:
стабильная сортировка вставками по возрастанию метрики. Переставляются указатели,
сами продукты не копируются; ссылки на оставшиеся продукты сохраняют силу.

Добавлено 16 тестов коллекции, всего 45 тестов: рост массива, удаление,
сумма метрик, сортировка, правило пяти, сохранение типов и очистка при ошибке
`clone()`. Демо-приложение пока не добавлено. Проверка утечек санитайзером
отдельна от тестов счётчика созданных и удалённых объектов:

```sh
cmake -S . -B build-asan -G Ninja -DCMAKE_BUILD_TYPE=Debug -DENABLE_SANITIZERS=ON
cmake --build build-asan
ctest --test-dir build-asan --output-on-failure
```

Для этой конфигурации нужен GCC/Clang с доступными библиотеками санитайзеров.
