# Отчёт по лабораторной работе № 4

**Тема:** полиморфизм и наследование.  
**Вариант:** 12 — мини-мир E «Банк».  
**Индивидуальное задание:** сортировка коллекции по `metric()`.

## Цель работы

Спроектировать абстрактный интерфейс банковского продукта, реализовать три
производных класса и полиморфную коллекцию. Применить виртуальные функции,
`dynamic_cast`, перегрузку операторов и управление динамической памятью.

## Контракт классов

### Базовый класс `Bank_Optional`

Класс задаёт общий интерфейс банковских продуктов и не хранит собственных
полей. Создать объект этого класса нельзя: он содержит чисто виртуальные методы.

| Метод | Назначение |
|---|---|
| `virtual double metric() const = 0` | Вычислить годовой эффект продукта |
| `virtual void read(std::istream&) = 0` | Прочитать и проверить поля |
| `virtual void print(std::ostream&) const = 0` | Вывести поля и метрику |
| `virtual Bank_Optional* clone() const = 0` | Создать независимую копию конкретного продукта |
| `virtual ~Bank_Optional() = default` | Обеспечить удаление наследника через базовый указатель |
| `explicit operator double() const` | Вернуть `metric()` при явном преобразовании |
| `bool operator==(const Bank_Optional&) const` | Сравнить метрики с абсолютной точностью `1e-6` |

`metric()`, `print()` и `clone()` сделаны чисто виртуальными, поскольку их
реализация зависит от конкретного продукта. Виртуальный деструктор имеет
реализацию по умолчанию: собственных ресурсов у базового класса нет.
Операторы преобразования и сравнения реализованы один раз в базовом классе
и используют виртуальный вызов `metric()`.

Свободные функции `operator<<` и `operator>>` принимают ссылку на базовый класс
и вызывают соответственно `print()` и `read()`. Благодаря этому операции
работают с любым наследником без проверки его типа внутри оператора.

Методы, не изменяющие состояние объекта, объявлены `const`. Ввод изменяет
объект и поэтому не является константным. Копирование полей конкретных
продуктов выполняется средствами компилятора: поля имеют простые типы и
не владеют динамической памятью. Виртуальное копирование обеспечивается
методом `clone()`.

### Производные классы

Все три класса публично наследуются от `Bank_Optional`, переопределяют общие
методы с `override` и имеют конструкторы по умолчанию и с параметрами.

| Класс | Поля | Специфичный метод |
|---|---|---|
| `Deposit` | `double sum_`, `double rate_`, `int years_`, `bool cumulative_` | `isCumulative() const` |
| `Credit` | `double sum_`, `double rate_`, `int years_`, `bool annuity_` | `isAnnuity() const` |
| `Card` | `double spending_`, `double rate_` | `hasCashback() const` |

Для суммы, расходов и ставки проверяется отсутствие отрицательных значений;
срок — положительным целым числом. Нарушение ограничений конструктора
вызывает `std::invalid_argument`. По умолчанию суммы и ставки равны нулю,
срок вклада и кредита — одному году, логические признаки — `false`.
Отдельные проверки бесконечности и `NaN` не выполняются.

В `Deposit` и `Credit` специфичный метод возвращает соответствующий признак.
`Card::hasCashback()` возвращает результат `rate_ > 0`.
В тестах вызов специфичных методов через базовые указатели предваряется
`dynamic_cast` и проверкой указателя на `nullptr`.

## Вычисление метрик

Во всех классах ставка задаётся долей: `0.1` означает 10%. Это единое
соглашение устраняет неоднозначность единиц ставки в формулах задания.

Для вклада без капитализации:

```text
metric = sum * rate
```

Для вклада с капитализацией:

```text
metric = sum * ((1 + rate)^years - 1) / years
```

Для кредита без аннуитетного признака:

```text
metric = sum * rate
```

Для аннуитетного кредита:

```text
r = rate / 12
n = years * 12
A = sum * r / (1 - (1 + r)^(-n))
metric = 12 * A
```

При представлении ставки в процентах в задании используется `rate / 1200`;
для принятой в программе доли эквивалентное выражение — `rate / 12`.
При нулевой ставке аннуитетная метрика равна `sum / years`, что исключает
деление на ноль. Аннуитетная метрика по условию — годовая сумма платежей,
включая погашение основного долга.

Для карты:

```text
metric = spending * rate
```

## Полиморфная коллекция

`BankCollection` использует собственный динамический массив `Bank_Optional**`.
Поле `size_` хранит число элементов, `capacity_` — вместимость массива.
При заполнении вместимость увеличивается, указатели переносятся в новый
массив, прежний массив указателей освобождается.

| Метод | Поведение |
|---|---|
| `add(Bank_Optional*)` | Добавить продукт и принять владение после успешного добавления |
| `remove(std::size_t)` | Удалить продукт и сдвинуть оставшиеся указатели |
| `size() const` | Вернуть количество продуктов |
| `at(std::size_t)` | Вернуть ссылку с проверкой индекса |
| `at(std::size_t) const` | Вернуть константную ссылку с проверкой индекса |
| `totalMetric() const` | Сложить метрики; для пустой коллекции вернуть ноль |
| `sortByMetric()` | Стабильно отсортировать продукты по возрастанию метрики |
| `swap(BankCollection&) noexcept` | Обменять массивы и их размеры |

Обход выполняется по индексам от нуля до `size() - 1` через `at()`.
Неверный индекс вызывает `std::out_of_range`. Добавление `nullptr` или того
же указателя повторно в эту коллекцию вызывает `std::invalid_argument`.
Передавать указатель на объект в стеке или объект другого владельца нельзя.
Если добавление завершается исключением, владение остаётся у вызывающего.

Коллекция удаляет продукты через базовые указатели. Виртуальный деструктор
гарантирует вызов деструктора фактического типа. Затем освобождается массив
указателей. Полиморфные продукты не передаются по значению как базовый класс,
поэтому срезки объектов нет.

### Правило пяти и безопасность копирования

Деструктор освобождает продукты и массив. Копирующий конструктор создаёт
новые продукты через `clone()`; в наследниках метод возвращает результат
`new Deposit(*this)`, `new Credit(*this)` или `new Card(*this)`.
Простого копирования указателей нет: две коллекции не владеют одним продуктом.

Если клонирование выбрасывает исключение, уже созданные копии и массив
освобождаются. Копирующее присваивание использует временную копию и `swap`:
при ошибке исходное содержимое цели сохраняется.

Перемещающий конструктор передаёт владение массивом и обнуляет поля источника.
Перемещающее присваивание освобождает прежнее содержимое цели через временный
объект. Обе перемещающие операции объявлены `noexcept`. После перемещения
источник остаётся пустым и пригодным к повторному использованию.

### Сортировка — индивидуальное задание

Реализована стабильная сортировка вставками. Очередной элемент сдвигается
влево, пока его метрика меньше метрики предыдущего продукта. Меняются местами
указатели, а сами продукты не копируются. При равных метриках сохраняется
исходный порядок. Для сравнения порядка используется обычное `>`, а не
приближённое равенство оператора `==`.

Сложность в худшем случае — `O(n²)`, дополнительная память — `O(1)`.
Пустая коллекция и коллекция из одного элемента обрабатываются корректно.
Добавление нового наследника с реализацией общего интерфейса не требует
менять код сортировки.

## Ввод и вывод

Краткий ввод содержит значения полей в порядке из задания:

```text
Deposit: 10000 0.1 2 1
Credit:  12000 0 2 1
Card:    10000 0.05
```

В этом примере имена слева обозначают тип объекта; при кратком вводе
пользователь вводит только числа. Логические поля принимаются строго как
`0` или `1`, затем преобразуются в `bool`.

Примеры полного вывода:

```text
Deposit: sum=10000 rate=0.1 years=2 cumulative=1 metric=1050
Credit: sum=12000 rate=0 years=2 annuity=1 metric=6000
Card: spending=10000 rate=0.05 metric=500
```

Чтение выполняется через обычное извлечение чисел из потока, без разбора подписей.

Ввод сначала выполняется во временные переменные. Временный объект создаётся
через проверяющий конструктор, и только после успеха изменяется текущий объект.
При ошибке формата или значений поток получает `failbit`, состояние объекта
сохраняется.

## Проверка программы

Тесты оформлены обычными `TEST` Google Test и вспомогательными функциями.
Пользовательских шаблонов, типизированных тестов и блоков `namespace` в файлах
тестов нет.

| Группа | Что проверяется |
|---|---|
| Продукты — 32 теста | Формулы, значения по умолчанию, ограничения, специфичные методы, успешный и неуспешный `dynamic_cast`, операторы, ввод и вывод, виртуальное удаление |
| Коллекция — 16 тестов | Пустое состояние, рост массива, смешанные типы, сумма метрик, удаление, запрет недопустимых указателей, сортировка, правило пяти, `swap`, очистка при исключениях |

Проверка выполнена в WSL2 с GCC 11.4.0 и C++20. Сборка использует
`-Wall -Wextra -Wpedantic`. Последний запуск после упрощения тестов:

```text
100% tests passed, 0 tests failed out of 48
```

При запуске были включены AddressSanitizer, UndefinedBehaviorSanitizer
и обнаружение утечек LeakSanitizer. В выполненных тестах ошибок памяти,
утечек и сообщений о неопределённом поведении не обнаружено.

## Воспроизведение проверки в WSL

Из каталога проекта, при установленных CMake 3.20+, Ninja и GCC/Clang:

```sh
cmake -S . -B build -G Ninja \
  -DCMAKE_BUILD_TYPE=Debug -DENABLE_SANITIZERS=ON
cmake --build build -j 2
ASAN_OPTIONS=detect_leaks=1 UBSAN_OPTIONS=halt_on_error=1 \
  ctest --test-dir build --output-on-failure
```

Google Test используется из установленного пакета; при его отсутствии
CMake загружает библиотеку через FetchContent, для чего нужен интернет.

Используется одна папка сборки — build, только для WSL/Linux. Пересборка: /usr/bin/cmake --build build. Запуск: ./build/bank_demo.

## Изменение проверки аргументов

Явные throw, try/catch и проверки, выбрасывавшие исключения, удалены по запросу. Конструкторы сохраняют переданные значения без проверки допустимости. Вызовы at/remove требуют корректного индекса, add — ненулевого уникального указателя на объект без другого владельца. Эти условия обязан соблюдать вызывающий код. Тесты ожидаемых исключений удалены. Прежние сведения отчёта о проверках аргументов и количестве тестов относятся к предыдущей версии. Стандартные операции выделения памяти по-прежнему могут выбрасывать исключения.
