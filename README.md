# Лабораторная работа 4 — вариант 12, «Банк»

Структура:

- `include/` — заголовки `Bank_Optional`, `Deposit`, `Credit`, `Card`, `BankCollection`.
- `src/` — реализации классов и демонстрационное приложение `main.cpp`.
- `tests/` — тесты Google Test.

Ставки задаются долями: `0.1` означает 10%. Для аннуитетного кредита
месячная ставка равна `rate / 12`. При нулевой ставке годовой платёж равен
`sum / years`.

## Сборка и тесты

Требуются CMake 3.20+, компилятор C++20 и Ninja для приведённых команд.
Google Test берётся из установленного пакета или скачивается при первой
конфигурации через FetchContent.

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

## Демонстрационное приложение

Из корня проекта после сборки, в WSL/Linux:

```sh
./build/bank_demo
```

В Windows PowerShell:

```powershell
.\build\bank_demo.exe
```

После запуска появляется меню:

| Пункт | Действие |
|---|---|
| 1 | Выбрать и создать вклад, кредит или карту |
| 2 | Показать коллекцию с индексами |
| 3 | Вычислить сумму метрик |
| 4 | Отсортировать продукты по возрастанию метрики |
| 5 | Удалить продукт по индексу |
| 6 | Вызвать специфичный метод выбранного продукта через `dynamic_cast` |
| 7 | Показать метрику через преобразование в `double` |
| 8 | Сравнить метрики двух продуктов |
| 0 | Завершить работу |

Для создания выберите пункт `1`, затем тип: `1` — вклад, `2` — кредит,
`3` — карта. Программа подскажет порядок числовых полей. Вводите все поля
продукта в одной строке. Индексы начинаются с нуля. После сортировки или
удаления смотрите их заново через пункт `2`. При неверном формате ввода
или недопустимом индексе меню покажет сообщение и предложит выбрать команду снова.
Пункт `6` проверяет результат `dynamic_cast` перед вызовом `isCumulative()`,
`isAnnuity()` или `hasCashback()`.

## Формат ввода

`read()` и `operator>>` принимают только числовые поля без подписей:

| Продукт | Порядок полей | Пример |
|---|---|---|
| `Deposit` | `sum rate years cumulative` | `10000 0.1 2 1` |
| `Credit` | `sum rate years annuity` | `12000 0 2 1` |
| `Card` | `spending rate` | `10000 0.05` |

Конструкторы проверяют неотрицательность сумм и ставок, положительный срок,
а также значения `0`/`1` для признаков капитализации и аннуитета.
Поля признаков хранятся как `bool`, параметры конструкторов принимаются как `int`.
При ошибке числового формата поток получает `failbit`. Ошибки значений из конструктора передаются как исключения без перехвата; объект сохраняет прежние значения.
Проверки бесконечности и `NaN` не выполняются.

`print()` выводит имя класса, поля и метрику. Ввод принимает только числа; формат вывода обратно не читается.
Подробный отчёт находится в [README_REPORT.md](README_REPORT.md).

## Коллекция

`BankCollection` хранит указатели на `Bank_Optional` в собственном динамическом
массиве. Вместимость увеличивается вдвое при заполнении. Успешный `add()`
передаёт владение объектом коллекции; при исключении объект остаётся у вызывающего.
Нельзя передавать указатель на локальный объект или объект другого владельца.
`nullptr` и повторное добавление того же указателя отклоняются.

`remove(index)` удаляет продукт и сдвигает оставшиеся элементы. Деструктор
удаляет все продукты через виртуальный деструктор базового класса и освобождает
массив. Копирование создаёт независимые объекты через `clone()`; при ошибке
копирования временные объекты освобождаются, а цель присваивания сохраняется.
Перемещение передаёт владение массивом, оставляя исходную коллекцию пустой
и пригодной для повторного использования.

Обход выполняется по индексам от `0` до `size() - 1` через `at()`.
Перегрузка `at()` для константной коллекции возвращает константную ссылку.
Некорректный индекс вызывает `std::out_of_range`.
`totalMetric()` суммирует метрики, для пустой коллекции возвращает `0`.

Индивидуальное задание варианта 12 реализовано в `sortByMetric()`:
стабильная сортировка вставками по возрастанию метрики. Переставляются указатели,
сами продукты не копируются; ссылки на оставшиеся продукты сохраняют силу.

Добавлено 16 тестов коллекции, всего 48 тест: рост массива, удаление,
сумма метрик, сортировка, правило пяти, сохранение типов и очистка при ошибке
`clone()`. Проверка утечек санитайзером
отдельна от тестов счётчика созданных и удалённых объектов:

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug -DENABLE_SANITIZERS=ON
cmake --build build
ctest --test-dir build --output-on-failure
```

Для этой конфигурации нужен GCC/Clang с доступными библиотеками санитайзеров.


При выводе продуктов в обычном формате показывается до шести значащих цифр. После печати исходная точность потока восстанавливается.

Текущий режим ввода: приложение печатает подсказки, пользователь вводит только числа. Поддержка чтения вывода с подписями удалена; симметрия print/read из ТЗ в этом режиме не выполняется.

Используется одна папка сборки — build, только для WSL/Linux. Пересборка: /usr/bin/cmake --build build. Запуск: ./build/bank_demo.

Блоки try/catch удалены из исходников и вспомогательных функций тестов. Проверки допустимых значений и EXPECT_THROW в тестах сохранены.

## Изменение проверки аргументов

Явные throw, try/catch и проверки, выбрасывавшие исключения, удалены по запросу. Конструкторы сохраняют переданные значения без проверки допустимости. Вызовы at/remove требуют корректного индекса, add — ненулевого уникального указателя на объект без другого владельца. Эти условия обязан соблюдать вызывающий код. Тесты ожидаемых исключений удалены. Прежние сведения отчёта о проверках аргументов и количестве тестов относятся к предыдущей версии. Стандартные операции выделения памяти по-прежнему могут выбрасывать исключения.
